# Matriz de políticas y reglas del Sistema de Gestión de Calidad

## Criterio de evaluación

Esta matriz compara las políticas funcionales solicitadas con el comportamiento comprobado en modelos, servicios, API y frontend. Las referencias indican los archivos o componentes principales donde se encontró cada regla; una política puede involucrar además serializers, rutas y pruebas relacionadas.

- **Implementada**: el comportamiento está presente de extremo a extremo o con el alcance descrito.
- **Parcial**: existe una parte verificable, pero falta algún estado, control, dato o interfaz de la política completa.
- **No encontrada**: no se encontró implementación comprobable en el código revisado.
- **Inconsistente**: existen comportamientos contradictorios, una interfaz que ofrece algo que el backend rechaza, o una denominación que no representa el dato real.

## Conclusión de la comparación solicitada

Las capacidades centrales —registro, clasificación administrativa, Observación directa o TRT, creación controlada de tratamientos, causas raíz, acciones, eficacia, indicadores, notificaciones y trazabilidad— están implementadas. La principal brecha frente a la política de referencia es semántica y de gobierno del cierre: el sistema no materializa toda la cadena propuesta como estados separados, no implementa un segundo cierre administrativo para Observaciones y no utiliza automáticamente `Reabierta` ante una eficacia negativa. También deben distinguirse el workflow genérico existente solo en backend y los circuitos operativos visibles de Observaciones y Tratamientos.
